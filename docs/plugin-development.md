# Разработка JavaScript-плагина

Исходники лежат в `web/plugin`. Готовый `web/static/kp.js` хранится в Git,
раздаётся Go-сервером и устанавливается в Lampa по прежнему адресу `/kp.js`.
Его не нужно редактировать вручную.

## Где искать код

| Модуль | Ответственность |
| --- | --- |
| `index.js` | Существующий публичный API плагина |
| `install.js` | Создание компонентов и подключение к Lampa |
| `config.js` | Версия, API и префикс настроек |
| `client.js` | OAuth, токены, обновление сессии и запросы KinoPub |
| `transport.js` | Сетевой адаптер Lampa и измерение времени запросов |
| `authorization.js` | Вход по коду, отмена, выход и описание устройства |
| `season-posters.js` | Обложки сезонов: точное сопоставление IMDb → TMDB |
| `playback.js` | Поиск соответствия карточке, запуск видео и очередь серий |
| `audio-labels.js` | Названия озвучек KinoPub в штатном меню аудиодорожек Lampa |
| `media.js` | Выбор потоков, сопоставление материалов и идентификаторы медиа |
| `progress.js` | Локальное хранение позиции просмотра |
| `progress-tracker.js` | События плеера, восстановление позиции и сохранение прогресса |
| `episode-playlist.js` | Ленивая загрузка следующих серий и отмена устаревших ответов |
| `catalog.js` | Разделы каталога, поиск, фильтры и папки закладок |
| `pages.js`, `pages.css` | Нативные страницы Lampa, фокус и оформление |
| `watch.js` | Подключение к штатной кнопке «Смотреть» |
| `settings.js` | Основные и дополнительные настройки |
| `diagnostics.js` | Ограниченная модель отчёта без URL и токенов |
| `player-feedback.js` | Понятные сообщения штатного плеера для видео Kinolamp |
| `player-diagnostics.js` | События плеера, ручные проверки и экран отчёта |
| `ui.js`, `text.js` | Нативные меню, сообщения и преобразование текста/URL |

Состояние принадлежит своему компоненту: окно входа — авторизации,
позиция и очередь — плееру, ревизия закладок — каталогу. Зависимости передаются
при создании; общего изменяемого реестра компонентов нет.

## Правила кода

- Понятные имена и явные действия. Не сокращай названия до одной буквы,
  кроме принятого в Lampa `$`. Комментарии объясняют причины, ограничения API
  и защиту от запоздавших ответов, а не повторяют операторы.
- Один модуль отвечает за одну область. Обычных функций достаточно:
  классы, контейнер внедрения зависимостей и фреймворк здесь не нужны.
- Условия всегда со скобками, одна декларация переменной на строку,
  строгое сравнение. `value == null` допустимо для общей проверки null/undefined.
- ESLint применяет рекомендованные правила и дополнительные запреты на
  `eval`, `new Function`, неявное выполнение строк и последовательности выражений.
  Единственное локальное исключение `no-control-regex` относится к намеренной
  проверке ASCII control characters в HTTPS-ссылках.
- Prettier задаёт отступы, переносы и кавычки. Стиль не правится вручную
  поверх результата форматтера.
- В исходниках используются ES-модули для разделения файлов. Исполняемый
  код сохраняет синтаксис ES5: `var`, обычные функции, без optional chaining,
  классов и async/await. ESLint отдельно разбирает **готовый** файл как ES5.
  Rollup не превращает современный синтаксис исходников в старый автоматически.
- Формат запросов KinoPub, ключи `kp_self_`, обработчики Lampa и публичный API
  не меняются ради косметического упрощения.
- Токены, подписанные URL и ответы API не попадают в Activity history,
  диагностические отчёты или консоль. Это ограничение сохраняется при переносе кода.

## Сборка и проверка

Нужен Node.js 24+. Все команды запускаются из корня проекта через Make:

```sh
make fmt-plugin      # lint с исправлениями, форматирование и сборка
make build-plugin    # сборка без изменения исходников
make check-plugin    # lint, форматирование, ES5 и актуальность kp.js
make coverage-js     # тесты собранного файла, покрытие 100/100/100
make check coverage  # общая проверка, включая Go и race detector
```

При первом запуске Make выполняет `npm ci --ignore-scripts` по lockfile.
Rollup, ESLint и Prettier — только инструменты разработки. Go-сборка, Docker
и установленный плагин обходятся без Node.js и npm.

`scripts/build-plugin.mjs` статически объединяет модули и встраивает локальные
CSS и SVG. Сборка не минифицируется и не загружает код по сети. Tree shaking
выключен: импортированные функции остаются в конечном файле и проверяются
существующими тестами. После сборки файл форматируется Prettier.

`make check-plugin` повторяет сборку в памяти и сравнивает результат побайтно
с файлом в Git. При расхождении проверка завершается ошибкой с командой
исправления. CI использует ту же проверку.

Тесты импортируют именно готовый `kp.js` и проверяют его браузерную обёртку,
а не отдельную альтернативную реализацию. Пороги покрытия строк, ветвей и функций
остаются 100%, без исключений. Обновляй тесты при изменении поведения и коммить
исходники вместе со сборкой. Проверка синтаксиса ES5 и mock Lampa не заменяют
проверку воспроизведения на конкретном телевизоре.
