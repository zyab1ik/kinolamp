# Разработка TypeScript-плагина

TypeScript-исходники (`.ts`) лежат в `web/plugin`. Готовый `web/static/kp.js` хранится в Git,
раздаётся Go-сервером и устанавливается в Lampa по короткому адресу `/kp`. Прежний `/kp.js`
остаётся полным совместимым алиасом, включая GET/HEAD, MIME, CORS и query-параметры.
Его не нужно редактировать вручную.

## Где искать код

| Модуль | Ответственность |
| --- | --- |
| `index.ts` | Существующий публичный API плагина |
| `contracts.ts`, `assets.d.ts` | Типы KinoPub, Lampa, UI, плейлиста, локального состояния и импортов CSS/SVG |
| `contracts.test-d.ts` | Проверки типов: неверные URL, индексы дорожек, параметры и настройки не становятся `any` |
| `install.ts` | Создание компонентов и подключение к Lampa |
| `config.ts` | Версия, API и префикс настроек |
| `client.ts` | OAuth, токены, обновление сессии и запросы KinoPub |
| `transport.ts` | Сетевой адаптер Lampa и измерение времени запросов |
| `authorization.ts` | Вход по коду, отмена, выход и описание устройства |
| `season-posters.ts` | Обложки сезонов: точное сопоставление IMDb → TMDB |
| `playback.ts` | Поиск соответствия карточке, запуск видео и очередь серий |
| `audio-labels.ts` | Названия озвучек KinoPub в штатном меню аудиодорожек Lampa |
| `media.ts` | Выбор потоков, сопоставление материалов и идентификаторы медиа |
| `progress.ts` | Локальное хранение позиции просмотра |
| `progress-tracker.ts` | События плеера, восстановление позиции и сохранение прогресса |
| `episode-playlist.ts` | Ленивая загрузка следующих серий и отмена устаревших ответов |
| `catalog.ts` | Разделы каталога, поиск, фильтры и папки закладок |
| `pages.ts`, `pages.css` | Нативные страницы Lampa, фокус и оформление |
| `watch.ts` | Подключение к штатной кнопке «Смотреть» |
| `settings.ts` | Основные и дополнительные настройки |
| `diagnostics.ts` | Ограниченная модель отчёта без URL и токенов |
| `player-feedback.ts` | Понятные сообщения штатного плеера для видео Kinolamp |
| `player-diagnostics.ts` | События плеера, ручные проверки и экран отчёта |
| `ui.ts`, `text.ts` | Нативные меню, сообщения и преобразование текста/URL |

Состояние принадлежит своему компоненту: окно входа — авторизации,
позиция и очередь — плееру, ревизия закладок — каталогу. Зависимости передаются
при создании; общего изменяемого реестра компонентов нет.

## Правила кода

- Понятные имена и явные действия. Не сокращай названия до одной буквы,
  кроме принятого в Lampa `$`. Комментарии объясняют причины, ограничения API
  и защиту от запоздавших ответов, а не повторяют операторы.
- Один модуль отвечает за одну область. Обычных функций достаточно:
  классы, контейнер внедрения зависимостей и фреймворк здесь не нужны.
- Условия всегда со скобками, одна декларация переменной на строку,
  строгое сравнение. `value == null` допустимо для общей проверки null/undefined.
- ESLint применяет рекомендованные правила и дополнительные запреты на
  `eval`, `new Function`, неявное выполнение строк и последовательности выражений.
  Единственное локальное исключение `no-control-regex` относится к намеренной
  проверке ASCII control characters в HTTPS-ссылках.
- Prettier задаёт отступы, переносы и кавычки. Стиль не правится вручную
  поверх результата форматтера.
- В исходниках используются TypeScript и ES-модули. `tsconfig.json` включает
  `strict`, `isolatedModules`, проверку регистра путей и `noEmit`. Нельзя
  отключать strict-проверки или добавлять `any`/`@ts-ignore` ради сборки.
- Сборщик сначала проверяет типы, затем TypeScript превращает модули в ES5,
  Rollup объединяет их, а Prettier сохраняет читаемый `kp.js`. Отдельный ESLint
  разбирает **готовый** файл как ES5. Полифилы и runtime TypeScript не добавляются;
  современные стандартные API могут отсутствовать на телевизоре даже при ES5 target.
- TypeScript закреплён на 5.9.3 ради поддержки ES5. Обновление компилятора
  требует отдельной проверки TV-совместимости, ESLint и отсутствия нового runtime.
- `contracts.ts` содержит только типы используемых методов Lampa и полей KinoPub.
  Типы не заменяют проверки недоверенных ответов: существующие runtime-проверки
  токенов, HTTPS, индексов, актуальности сессии и доступности методов сохраняются.
  В callback ответы читаются после проверки ошибки; non-null assertions отмечают
  эту договорённость транспортного адаптера и состояния внутри жизненного цикла.
- Импорты TypeScript оставляют суффикс `.js` по правилам ES-модулей; сборщик
  разрешает локальные ссылки на `.ts`, а `import type` удаляется полностью.
- Формат запросов KinoPub, ключи `kp_self_`, обработчики Lampa и публичный API
  не меняются ради косметического упрощения.
- Токены, подписанные URL и ответы API не попадают в Activity history,
  диагностические отчёты или консоль. Это ограничение сохраняется при переносе кода.

## Сборка и проверка

Нужен Node.js 24+. Все команды запускаются из корня проекта через Make:

```sh
make fmt-plugin      # lint с исправлениями, форматирование и сборка
make typecheck       # строгая проверка типов без вывода JS
make build-plugin    # проверка типов и сборка без изменения исходников
make check-plugin    # типы, lint, форматирование, ES5 и актуальность kp.js
make coverage-js     # тесты собранного файла, покрытие 100/100/100
make check coverage  # общая проверка, включая Go и race detector
```

При первом запуске Make выполняет `npm ci --ignore-scripts` по lockfile.
Rollup, ESLint и Prettier — только инструменты разработки. Go-сборка, Docker
и установленный плагин обходятся без Node.js и npm.

`scripts/build-plugin.mjs` статически объединяет модули и встраивает локальные
CSS и SVG. Сборка не минифицируется и не загружает код по сети. Tree shaking
выключен: импортированные функции остаются в конечном файле и проверяются
существующими тестами. После сборки файл форматируется Prettier.

`make check-plugin` повторяет сборку в памяти и сравнивает результат побайтно
с файлом в Git. При расхождении проверка завершается ошибкой с командой
исправления. CI использует ту же проверку.

Тесты импортируют именно готовый `kp.js` и проверяют его браузерную обёртку,
а не отдельную альтернативную реализацию. Пороги покрытия строк, ветвей и функций
остаются 100%, без исключений. Обновляй тесты при изменении поведения и коммить
исходники вместе со сборкой. Проверка синтаксиса ES5 и mock Lampa не заменяют
проверку воспроизведения на конкретном телевизоре.
