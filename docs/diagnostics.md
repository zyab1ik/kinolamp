# Диагностика воспроизведения

Открой **Настройки → Kinolamp → Дополнительно → Диагностика воспроизведения**.
Включи локальную диагностику, затем заново запусти фильм или серию. После
зависания вернись в это меню и выбери «Показать отчёт». «Скачать отчёт JSON»
создаёт файл на устройстве только по нажатию; на некоторых телевизорах
скачивание недоступно, но отчёт можно открыть на экране.

Сбор выключен по умолчанию. Предпочтение включения хранится локально, сами
события — только в памяти текущего экземпляра плагина. Хранится не более 120
последних событий; периодические замеры — не чаще раза в пять секунд, без
отдельного таймера. Перезапуск удаляет события. Выключение и «Очистить отчёт»
также удаляют записи и последнюю ссылку для проверки CDN, снимают обработчики
видео и отменяют ожидающий HEAD-запрос. Запоздавшие ответы ручных проверок не
восстанавливают очищенный отчёт. При выключенном сборе дополнительные сетевые
запросы и замеры не выполняются.

## Что видно в отчёте

| Событие / поле | Значение |
| --- | --- |
| `api`, `proxy` / `ms` | Время существующего запроса API или подготовки HLS-ticket. OAuth-запросы не записываются. |
| `source` / `mode`, `format`, `height` | Прямой режим / свой прокси, формат и выбранное разрешение. |
| `prepare` / `ms` | Подготовка видео от получения ссылок до передачи плееру; при ручных диалогах включает время выбора пользователя. |
| `start`, первый `playing` / `ms` | Старт Lampa и время от команды запуска до первого доступного события фактического воспроизведения. Внешний плеер может не прислать `playing`. |
| `waiting`, `stalled`, `sample` / `buffer` | Ожидание данных, остановка загрузки и доступные замеры. Запас буфера в секундах считается только для диапазона, содержащего текущую позицию, а не для последнего произвольного диапазона. |
| `current`, `readyState`, `width`, `height` | Позиция в секундах, готовность и размеры видео, если доступны в этом плеере. |
| `error` / `detail`, `fatal` | Только разрешённый код ошибки HLS и флаг фатальности. Текст ошибки и адрес не сохраняются. Неизвестные сообщения заменяются `other` либо остаются без кода. |
| `path`, `nativeHls` | `mse` означает источник `blob:`, `direct_src` — обычный источник видео. `nativeHls` показывает заявленную поддержку HLS браузером. Эти признаки не являются универсальным определением реально выбранного движка. |
| `at` | Миллисекунды относительно начала текущего сбора, без календарной даты. |

У чужого источника Lampa события не собираются. Доступность полей зависит от
плеера: отсутствие измерения не означает нулевой буфер или отсутствие ошибки.
HLS-коды сверены с теми, которые Lampa передаёт через `PlayerVideo.listener`;
обработка самого видео, переключение движка, размеры буфера и повторы запросов
не меняются. На системном плеере телевизора часть показателей недоступна.

## Ручные проверки

«Проверить доступность API / прокси / CDN» открывает выбор проверки. Каждый
запрос выполняется только по нажатию, при включённом сборе:

- API: обычный запрос KinoPub `/types`, без сохранения тела ответа.
- Свой прокси: публичный `/health` по настроенному HTTPS-адресу. Ключ прокси не
  передаётся. Это проверка здоровья приложения, не проверка авторизации HLS.
- CDN: `HEAD` последнего выбранного URL источника с таймаутом 15 секунд, без
  добавления OAuth/proxy-заголовков и без cross-origin credentials. Ссылка
  удерживается только в памяти для этой проверки, в отчёт и хранилище не попадает.
  После очистки нужно вновь выбрать видео. Одновременные проверки CDN запрещены.

Результаты: `ok`, `error`, `timeout`, `network_or_cors`, `not_configured`,
`unsupported`, `cancelled`. Там, где браузер разрешает прочитать HTTP-статус,
он показывается числом; `0` не является HTTP-ответом сервера. Для успешного
JSON-callback Lampa используется условный статус 200, поскольку Reguest не
передаёт точный успешный статус. Браузер может запретить HEAD/CORS или сервер
может не поддерживать HEAD, хотя воспроизведение работает. Эти проверки не
измеряют пропускную способность, не проверяют каждый сегмент и не доказывают
причину зависания. Ответ 403 также может означать истёкшую ссылку.

## Приватность и проверка

Вместо маскирования произвольных логов используется разрешённый набор полей:
константные коды, ограниченные числа и булевы значения. Произвольные строки,
URL, заголовки, тела запросов/ответов, имена материалов, Client Secret,
OAuth-токены, proxy-ключи и коды активации не принимаются в журнал. Экспорт и
экранный отчёт строятся из одной безопасной структуры. Отчёт никуда не
отправляется автоматически; публичный сервер не получает новые логи.
Это относится к диагностике Kinolamp, а не к сторонней консоли самой Lampa.

`make coverage` проверяет 100% Go statements и JS lines/branches/functions,
включая подстановку секретов и циклических объектов, лимит записей, недоступные
API видео, HTTP/сеть/CORS/таймаут, очистку, отключение, отмену и экспорт.
UI и получение событий проверяются отдельно в Lampa; поддержка конкретной
модели телевизора требует проверки на устройстве.

## Сообщение bufferFullError на телевизоре

`bufferFullError` — переполнение медиабуфера HLS-плеера. `fatal=false` означает,
что ошибка отмечена движком как нефатальная; это не гарантирует непрерывное
воспроизведение. Это отличается от ошибки скачивания фрагмента `fragLoadError`.

Для своих потоков Kinolamp заменяет известные нефатальные HLS-сообщения
понятным текстом в штатном PlayerInfo Lampa. Фатальные и неизвестные ошибки
обрабатывает сама Lampa. Исходный код остаётся в локальном отчёте, если сбор
диагностики включён. Плагин не подменяет движок HLS, не меняет глобальные
настройки плеера и не выдаёт перевод сообщения за исправление причины зависания.

Если после переполнения видео останавливается, перезапусти воспроизведение
или проверь другой доступный плеер в настройках Lampa. Для дальнейшего разбора
включи локальную диагностику и воспроизведи проблему на том же устройстве.
