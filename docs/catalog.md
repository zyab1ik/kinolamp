# Каталог KinoPub в Lampa

Карточки оформлены ближе к каталогу KinoPub: основное название и оригинальное
название показаны отдельно, под ними — год и доступные жанры. Качество
(`1080p`, `UHD 4K`) и наличие AC3 отмечены на постере; рейтинг IMDb показывается
только при наличии корректного значения в ответе KinoPub. Постер берётся из
доступной версии `big`, затем `medium` или `small`. Недостающие метаданные
не заменяются вымышленными рейтингами или характеристиками.

Кнопка **«Разделы»** открывает библиотеку: новинки, фильмы, сериалы,
документальные фильмы и сериалы, концерты, ТВ-шоу и 3D-фильмы.
Разделы используют типы из [документации API KinoPub](https://kinoapi.com/api_video.html).
Кнопка текущего порядка выдачи позволяет выбрать дату добавления, обновление,
рейтинг KinoPub или число просмотров. Это серверная сортировка `sort`,
а отметка IMDb на карточке — отдельное поле `imdb_rating`.
Сортировка и фильтры сохраняются при переходе между страницами.
Следующие карточки подгружаются при достижении конца прокрутки Lampa или
приближении фокуса к последним карточкам. Текущий список дополняется, а не
заменяется: выбранная карточка и возврат Back сохраняются. Одновременно
выполняется один запрос. После ошибки появляется «Повторить»; автоматических
повторов нет. Пустая страница, конец выдачи или страница из одних повторов
останавливают подгрузку. Ответы для закрытой, обновлённой страницы или
изменившегося аккаунта не добавляются в каталог.

Каталог наследует шрифт Lampa и использует её штатный класс `card__title`.
Собственный шрифт и отдельные файлы шрифтов плагин не подключает.

Это адаптация каталога к Lampa, а не копия веб-сайта: точное совпадение
состава и порядка выдачи kino.watch не гарантируется. Они могут зависеть
от выбранного раздела, сортировки, настроек аккаунта и возможностей API.

После установки плагина в левом меню Lampa появляется **KinoPub**.
Войди в аккаунт через Настройки → Kinolamp, затем открой этот пункт.
Запасной вход находится в Настройки → Kinolamp → Дополнительно → Открыть
каталог KinoPub. Сборки без нативных Activity требуют обновления Lampa.

Вверху страницы доступны:

- **Новинки** — недавно добавленные материалы KinoPub, сортировка `created-`.
- **Фильмы / Сериалы** — каталог соответствующего типа с сортировкой `updated-`.
- **Поиск** — штатная клавиатура Lampa, запрос от трёх символов. Сохраняется не
  история ввода клавиатуры, а только запрос в текущем маршруте Activity для Back.
- **Избранное** — существующие папки закладок аккаунта KinoPub и их содержимое.
- **Фильтры** — жанр и качество из справочников API. Они доступны в разделах
  каталога; API поиска и закладок не документирует эти фильтры, там их нет.

Карточка фильма запускает существующий сценарий просмотра, сериал открывает
выбор сезона и серии. Управление осуществляется штатными фокусом, навигацией,
клавиатурой, меню выбора и кнопкой Back Lampa. Отдельной кнопки «Назад» нет.
Подгрузка сохраняет сортировку и фильтры; смена раздела или сброс очищают фильтры.

## Закладки аккаунта

Удерживай OK/Enter на карточке каталога или результата поиска. В меню появятся
папки аккаунта: можно добавить материал или удалить его из конкретной папки,
если он уже присутствует. Если папок ещё нет, отдельное действие
**«Создать папку „Избранное“ и добавить»** создаёт первую папку.
Удаление папок и удаление материала сразу из всех папок не выполняются.

Изменение отправляется в KinoPub только после явного выбора пользователя.
Сообщение об успехе появляется после успешного ответа, затем страница
перезагружается из API. Отмена и переход на другую страницу отбрасывают
устаревшие ответы; уже отправленная операция в аккаунте может завершиться,
даже если пользователь ушёл со страницы. Автоматических повторов POST после
сетевой ошибки нет, кроме штатного обновления авторизации после HTTP 401.

Каталог и поиск запрашиваются по 20 карточек с пагинацией API. Для папок и
их содержимого документация возвращает полный список без параметров
пагинации: он делится на страницы локально по 20 элементов. Если конкретный
сервер KinoPub ограничивает этот ответ недокументированным способом, это
требует отдельной проверки на аккаунте. Пустые списки имеют пояснение, ошибка
загрузки — кнопку «Повторить».

## Возможности API и ограничения

Используются только API KinoPub и постеры из его метаданных:

| Действие | API |
| --- | --- |
| Каталог / новинки | `GET /items`, `type`, `sort`, `genre`, `quality[]`, `page`, `perpage` |
| Поиск | `GET /items/search`, `q`, `page`, `perpage` |
| Справочники фильтров | `GET /genres`, `GET /references/video-quality` |
| Папки / содержимое | `GET /bookmarks`, `GET /bookmarks/<id>` |
| Папки материала | `GET /bookmarks/get-item-folders?item=<id>` |
| Добавление / удаление | `POST /bookmarks/add`, `POST /bookmarks/remove-item`, с `item` и `folder` |
| Первая папка | `POST /bookmarks/create`, с `title` |

Фильтр каталога по озвучке не обещается: в документации `/items` его нет.
Справочники типов/авторов перевода сами по себе не подтверждают поддержку
фильтра. Озвучка выбирается в существующем плеере.

Названия, подписи и метаданные отображаются как текст, ссылки на постеры
проверяются как HTTPS. В Activity передаются только скалярные параметры
маршрута, без токенов, media URL, DOM и callback. Запросы идут непосредственно
к KinoPub, сервер Kinolamp не получает новую историю поиска или закладок.
Глобальное поведение и другие источники самой Lampa не изменяются.

Контракты: [видео и поиск](https://kinoapi.com/api_video.html),
[закладки](https://kinoapi.com/api_bookmarks.html),
[справочники](https://kinoapi.com/api_references.html).
Автоматические тесты проверяют маршруты, пагинацию, фильтры, безопасное
отображение, POST-операции, ошибки, создание первой папки и устаревшие
ответы при отмене. Локальный предпросмотр использует явно помеченные тестовые
ответы; он не подтверждает наличие этих фильмов в аккаунте KinoPub.
