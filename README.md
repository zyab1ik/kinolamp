# Kinolamp — KinoPub для Lampa

Плагин KinoPub для Lampa на телевизорах, приставках и в браузере.
Один из удобных сценариев — Samsung Tizen с Media Station X.
Удобный сценарий на телевизоре: **Media Station X (MSX) → Lampa → Kinolamp → KinoPub**.
Если Lampa уже настроена в MSX, добавь Kinolamp в её расширения и выбирай кино
с пульта: отдельный клиент KinoPub на телевизоре устанавливать не требуется.

Плагин также можно использовать в браузерной Lampa и на других устройствах,
где она работает. Поддержка видео и дорожек зависит от плеера и модели телевизора;
совместимость конкретной связки Tizen/MSX нужно проверять на устройстве.
[Платформы Media Station X](https://msx.benzac.de/info/?tab=PlatformSupport).

Инфраструктура владельца — Go-сервер для своего VPS: один бинарник со встроенными
`kp.js` и страницей установки. Node.js в production не нужен.
Версия исходников указана в [VERSION](VERSION), опубликованные сборки — в
[GitHub Releases](https://github.com/zyab1ik/kinolamp/releases).
Самостоятельная реализация плагина и Go-сервера. Для входа используется тот же общий OAuth-клиент xbmc, что и в `mainsync-afk/lampa_kinopub` и открытых клиентах KinoPub; это данные приложения, не персональный токен пользователя.

## Установка на устройство

На **Samsung Tizen через Media Station X** сначала открой уже настроенную
Lampa внутри MSX. Все следующие действия — добавление расширения, вход,
каталог и просмотр — выполняются в самой Lampa. Обычная навигация работает с пульта.

Для браузера используем [Lampa по HTTPS](https://cf.lampa.mx/). При переходе с HTTP настройки и расширения нужно добавить заново: это отдельный origin браузера.
Адрес плагина нашей установки: `https://kp.eu3.filefor.net/kp.js`.

1. В Lampa открой Настройки → Расширения → Добавить и вставь `https://kp.eu3.filefor.net/kp.js` (для своего сервера — его HTTPS-адрес с `/kp.js`).
2. Перезапусти Lampa. Открой Настройки → Kinolamp.
3. Открой **Настройки → Kinolamp → Войти в KinoPub**. Появится окно с кодом. Оставь его открытым. Поля Client ID/Secret заполнять не требуется.
4. На телефоне или в другой вкладке открой адрес из окна плагина (сейчас `https://kino.watch/device`), войди в аккаунт KinoPub. В «Активация устройства» введи **код из Lampa** и нажми «Добавить». Сайт код не выдаёт — он его принимает.
5. Вернись в Lampa и дождись сообщения «KinoPub: вход выполнен». Затем открой **левое меню → KinoPub** для собственного каталога или карточку фильма/сериала в Lampa → **Смотреть**. В современных сборках Lampa фильм запускается сразу, сериал открывает выбор сезона и серии. Долгое нажатие «Смотреть» открывает список источников. Старые сборки сохраняют путь **Смотреть → KinoPub**. Отдельной кнопки Kinolamp на карточке нет.

Если плагин уже установлен и показывает «200 Рабочий», перезапусти Lampa и начни с шага 3. Статус 200 подтверждает загрузку JavaScript, а не авторизацию аккаунта. Если видишь старые OAuth-поля, нужна перезагрузка обновлённого плагина. Истёкший код можно получить заново через «Войти в KinoPub». Для первого просмотра HLS-прокси оставь выключенным.

Общий клиент проверен 28 октября 2026: API вернул 200, device/user code и CORS `*` для запроса с origin `https://cf.lampa.mx`. Проверка не активирует пользовательский аккаунт и не доказывает воспроизведение на телевизоре. Клиент может быть отозван сервисом; ошибка `invalid_client` показывается отдельно. Личный access/refresh-токен хранится только после подтверждения владельцем аккаунта. Старые сохранённые client_id/client_secret больше не используются.

Публичные файлы плагина поддерживают GET/HEAD и CORS без cookie, чтобы проверка
расширений в браузерной Lampa могла прочитать JavaScript. Название «Kinolamp»
записывается только для собственной безымянной записи расширения; пользовательское
название и другие плагины сохраняются. Значок доступен как `/icon.svg` и показан
в настройках, списке источников «Смотреть» и на странице установки. API HLS-прокси сохраняет отдельные
проверки ключа и разрешённых origin.

Нужна действующая подписка и разрешённый доступ к KinoPub. Если конкретная браузерная сборка Lampa блокирует прямой API из-за CORS, эта версия не обходит ограничение публичным CORS-прокси. Проверяй на используемом клиенте; универсальная совместимость не заявляется.

Kinolamp особенно удобен для Samsung Tizen, LG webOS и других Smart TV, где уже работает Lampa, а отдельный клиент KinoPub установить сложно. Фильмы и серии можно выбирать в интерфейсе Lampa с пульта. Поддержка форматов и дорожек зависит от конкретного плеера; проверка на физических телевизорах ещё требуется.

После входа и при запуске плагин обновляет описание текущего устройства через официальный `POST /v1/device/notify`: название `Kinolamp / Lampa`, платформа Lampa (например `tizen`, `webos`, `browser`) и версия плагина. Это обновление уже активированного устройства, без создания дополнительного слота. Существующая запись `unknown` обновится после перезапуска, если локальная сессия сохранена и запрос успешен. Ошибка обновления описания не блокирует просмотр.

## Как пользоваться после входа

- **Найти кино:** левое меню → KinoPub → Новинки, Фильмы или Сериалы. Для самостоятельного поиска нажми «Поиск»; введи минимум три символа. Жанр/качество задаются через «Фильтры», следующая страница сохраняет выбранные фильтры.
- **Сохранить на потом:** удерживай OK/Enter на карточке и выбери папку KinoPub. Если папок нет, отдельное действие создаст «Избранное» и добавит материал. Папки доступны через «Избранное» в каталоге; удаление выполняется из конкретной папки.
- **Посмотреть сериал:** выбери сезон и эпизод. Следующая/предыдущая серия доступны в штатном плейлисте Lampa. Для автоматического продолжения используй настройку автоперехода плейлиста в Lampa; отдельного переключателя Kinolamp нет.
- **Продолжить просмотр:** на обычном пути через «Смотреть» и страницы серий позиция подхватывается автоматически, если используемый плеер поддерживает события прогресса. В совместимом меню старых сборок есть отдельный выбор продолжения/начала сначала. Общий сброс находится в Настройки → Kinolamp → Дополнительно и требует подтверждения.
- **Разобрать зависание:** включи Настройки → Kinolamp → Дополнительно → Диагностика воспроизведения → Локальная диагностика, затем заново запусти видео. После проблемы открой отчёт. Сбор по умолчанию выключен, хранит до 120 событий в памяти и очищается при выключении/перезапуске. API, свой прокси и последний CDN проверяются только вручную.

События диагностики зависят от плеера. HEAD/CORS-проверка CDN не измеряет скорость
видео и не доказывает причину зависания. Экран и JSON используют безопасную
структуру без токенов и подписанных URL; возможность скачивания зависит от
клиента, во встроенном браузере факт получения файла ещё не подтверждён.

## Запуск своего сервера

Требования: Docker Compose на VPS, домен с DNS на VPS, HTTPS reverse proxy.

```sh
git clone git@github.com:zyab1ik/kinolamp.git
cd kinolamp
cp configs/kinolamp.env.example .env
make up
make health
```

Размести reverse proxy на `https://lampa.example.com` → `127.0.0.1:8788`.
Пример для установленного на хосте Caddy — [deployments/Caddyfile](deployments/Caddyfile).
Измени пример домена на свой; Caddy получит TLS-сертификат. HTTPS нужен и между внешним reverse proxy и origin, если они на разных серверах. Не включай кеширование или access/error-логи с полными HLS ticket URL.

Если домен подключается через внешнюю панель хостинга, укажи в панели **VPS port 8788**
и выставь `BIND_ADDRESS=0.0.0.0` в локальном `.env`: шлюз панели не сможет обратиться
к loopback-интерфейсу VPS. Порт контейнера остаётся `3000`. Дополнительный публичный
TCP-проброс не требуется, если панель сама предоставляет HTTPS-домен. Проверяй
HTTPS на стороне панели; отдельное шифрование до origin зависит от сети провайдера.

Без Docker: Go 1.27+, `make run`; по умолчанию слушает только `127.0.0.1:3000`.
`make build` создаёт `bin/kinolamp` со встроенными ресурсами. Параметр `LISTEN_ADDR` меняет адрес прослушивания. Для запуска без Docker переменные из `.env` необходимо передать процессу самостоятельно. Node.js 24+ нужен только для разработки: сборки плагина, lint и тестов. У Go-сервера и готового плагина нет внешних runtime-зависимостей; npm-инструменты разработки закреплены в lockfile.

## Опциональный HLS-прокси

Для прямого просмотра оставь `ENABLE_PROXY=false`. Сервер тогда только раздаёт плагин и страницу установки.
Для проблемных HLS4 на Tizen:

1. Создай локально ключ `openssl rand -hex 32` и запиши его в `.env` как `PROXY_TOKEN`. Не добавляй `.env` в Git.
2. Укажи `ENABLE_PROXY=true`, свой HTTPS-origin `PUBLIC_BASE_URL` и `CDN_HOSTS`.
3. В `CDN_HOSTS` укажи **только доверенные CDN-домены фактических ссылок KinoPub**: `edge.trusted-cdn.tld` — точный хост; `.trusted-cdn.tld` — домен и его поддомены. Пример намеренно не задаёт список разрешений: CDN меняются, автоматического доверия произвольным хостам нет.
4. В `ALLOWED_ORIGINS` укажи origin самого приложения Lampa: для нашей браузерной установки `https://cf.lampa.mx`. Несколько origin разделяются запятыми. `null` добавляй только при необходимости для своего file/native-клиента. CORS не заменяет ключ.
5. Пересоздай контейнер: `make up`.
6. В **Настройки → Kinolamp → Дополнительно** включи «Использовать свой HLS-прокси», укажи `https://lampa.example.com` и этот ключ.

Плагин отправляет `POST /api/manifests` с `Authorization: Bearer <PROXY_TOKEN>` и JSON `{master, voice, maxHeight}`. Сервер скачивает и сокращает master, возвращает случайный 256-битный `/hls/<ticket>.m3u8` со сроком жизни 5 минут. Native AVPlayer может открыть его без поддержки заголовков. Ключ VPS и исходная ссылка не помещаются в ticket URL. Ticket — временная ссылка доступа: не публикуй её.

Сегменты и дочерние плейлисты загружаются устройством прямо с CDN KinoPub. Сервер видит исходную подписанную ссылку, выбранную озвучку, качество и IP; OAuth-токены KinoPub на VPS не передаются. HTTP и перенаправления upstream запрещены. DNS-ответы проверяются и фиксируются для исходящего HTTPS-соединения с обычной проверкой сертификата/SNI. Переменные HTTP_PROXY/HTTPS_PROXY не используются для upstream. Локальные, специальные IP и IP-литералы запрещены. Домены ссылок в выдаваемом master также должны входить в allowlist.

Ограничения: 1 MiB на upstream master, 10 секунд на DNS+загрузку, 4 параллельных запроса, 30 запросов создания ticket в минуту на socket IP, 256 ticket в памяти. За reverse proxy socket IP общий — лимит будет общим для пользователей. Хранилища на диске нет. Перезапуск контейнера аннулирует ticket. Первичный HTTPS DNS-путь фиксируется сервером; DNS дочерних CDN-ссылок разрешает сам плеер. Разрешай только доверенные CDN.

## Структура проекта

Применены каталоги из [golang-standards/project-layout](https://github.com/golang-standards/project-layout):
`cmd/kinolamp` — точка входа; `internal/app` — сервер, конфигурация и HLS;
`web/plugin` — читаемые исходники плагина; `web/static` — готовый плагин и страница установки; `configs` — шаблоны настроек;
`build/package` — Dockerfile; `deployments` — Compose и Caddy;
`test` — проверки JavaScript; `docs` — документация.
Подробности и границы пакетов — [docs/architecture.md](docs/architecture.md).

## Управление через Make

`make help` показывает все команды. Основные: `make run`, `make build`, `make check`, `make test`, `make coverage`, `make docker-build`, `make up`, `make down`, `make logs`, `make health`, `make clean`.

## Разработка плагина

Редактируй модули в `web/plugin`, а не собранный `web/static/kp.js`.
Вход, API, плеер, каталог, настройки и диагностика разделены по назначению.
Стили страниц лежат в `web/plugin/pages.css`, иконка — в `web/static/icon.svg`.

```sh
make fmt-plugin     # единый стиль исходников и пересборка kp.js
make build-plugin   # только пересборка
make check-plugin   # ESLint, Prettier, ES5 и совпадение сборки с исходниками
make coverage-js    # тесты готового файла: строки, ветви и функции — 100%
```

Make сам установит закреплённые dev-зависимости через `npm ci` при первом запуске.
Коммить исходники и полученный `kp.js` вместе. Файл остаётся читаемым,
без минификации и загрузки других скриптов. Для установки в Lampa ссылка не меняется.
Правила и карта модулей — [docs/plugin-development.md](docs/plugin-development.md).

## Обновления и проверки

```sh
make check
make test
make coverage
make build
git pull --ff-only
make up
```

GitHub Actions запускает `make check`, `make coverage`, `make build`, а также сборку/read-only запуск Docker. `make coverage` требует 100% statement coverage всего Go-кода, включая точку входа, и 100% lines/branches/functions всего `web/static/kp.js`; исключений или ignore-директив нет. Проверка Go читает непокрытые блоки напрямую и не полагается на округлённый процент. Тесты проверяют OAuth, конкурентное обновление токенов, отмену входа, отказ от SSRF, фиксацию DNS, лимиты upstream, защиту API, ticket и выбор HLS-дорожек. Интеграционные проверки Lampa используют совместимый mock API; реальное устройство и подписка нужны для финального playback-теста. Плагин не проходил проверку на физическом телевизоре при создании репозитория.

## Страницы KinoPub

В левом меню доступен [отдельный каталог KinoPub](docs/catalog.md): новинки,
фильмы, сериалы, самостоятельный поиск, фильтры жанра/качества и папки закладок
аккаунта. Долгое нажатие на карточку открывает добавление/удаление из папки.

В современных сборках Lampa результаты поиска, сезоны и серии открываются полноценными страницами с постерами, управлением пультом и стандартной навигацией Назад. Фильм с точным совпадением названия, года и типа либо IMDb ID запускается сразу. Если совпадение неоднозначно, нужно выбрать результат. Пустой экран «Видео 1» не открывается для фильма с одним видео. Качество выбирается автоматически в пределах настройки и меняется штатным управлением плеера; просмотр продолжается с сохранённой позиции. В HLS-прокси при наличии дорожек остаётся выбор озвучки. Старые сборки без API Activity используют совместимое меню.

На основном экране настроек остаются качество, вход либо выход, «Дополнительно» и сведения о плагине. Прокси и сброс прогресса находятся в «Дополнительно»; адрес и ключ видны только при включённом прокси. Сброс требует подтверждения. Навигация назад выполняется штатной стрелкой Lampa или кнопкой Back на пульте.

## Публикация версий

Версия хранится в `VERSION` и проверяется на совпадение с плагином. После слияния PR с новой версией main автоматически выполняет все проверки, деплой и итоговый отчёт, затем публикует GitHub Release с `kp.js`, SVG-логотипом, Go-сервером Linux amd64/arm64 и SHA256SUMS. Пропущенный или неуспешный деплой блокирует публикацию. Уже опубликованная версия пропускается; для следующего релиза увеличь `VERSION` в PR. Ручной тег не запускает релиз. Подробности — [docs/releases.md](docs/releases.md).

## Автодеплой из main

CI показывает отдельные этапы анализа кода, Go, JavaScript, Docker, деплоя и итоговый отчёт. После успешных проверок main передаёт на VPS тот же Docker-образ, который проверялся в CI. Деплой других веток и PR пропускается. Активация требует отдельного ключа Actions; до настройки переменной `DEPLOY_ENABLED=true` выкладка выключена.

Настройка, проверка ключа сервера и откат описаны в [docs/deployment.md](docs/deployment.md).

Исходные спецификации: [KinoPub OAuth](https://kinoapi.com/authentication.html), [KinoPub video API](https://kinoapi.com/api_video.html), [Lampa](https://github.com/yumata/lampa).
